A one page guide to where things live. Snapshot of the code at the commit that added this file; it can drift as the code changes.

What it is

A Discord bot with two jobs. /previously gives you a private, TV narrator style recap of what you missed in a channel, every line linked to the real message. Reruns reply to a question the channel already answered, with a link to the answer and how many times it's been asked.

The main pieces: the bot entry (src/index.js), a history reader (Discord already stores the chat, so nothing is saved), two Claude calls (Opus for recaps, Haiku for reruns), and a grounding check in plain code that decides what's real.

One action, end to end: typing /previously

Reference route (3 stops)

  1. Entry: src/index.js, search for Events.InteractionCreate. Defers a private reply, checks permissions, reads history, handles the quiet, missing permission and failure states.
  2. The model call: src/recap.js, function writeRecap. Sends the chat as data with cache_control on the chat block and asks for JSON lines that each name a message_id.
  3. The part that keeps it honest: src/grounding.js, function groundRecap. Keeps only lines whose id is a real message we sent, in chat order, max 6, links and slurs stripped. Tested in test/grounding.test.js.
Same idea for reruns

src/index.js Events.MessageCreate → src/questions.js looksLikeQuestion → src/reruns.js buildCandidates (groups identical questions so spam can't push the real one out) and findRerun (Claude Haiku, earlier questions cached) → src/grounding.js groundRerun (needs confident: true and real ids, otherwise the bot stays quiet).

To change this, start here

  • The recap's voice or what it picks: the SYSTEM prompt in src/recap.js.
  • How the recap looks: recapEmbed in src/replies.js (title, colour CRT_COLOUR, "Jump to this message" links).
  • The rerun wording or the 💀 counter: rerunText in src/replies.js.
  • What counts as a question: QUESTION_WORDS in src/questions.js, with tests in test/questions.test.js.
  • Cooldown, how far back to read: COOLDOWN_MS in src/reruns.js, MAX_MESSAGES in src/history.js.
  • Models and prices: src/claude.js.

A practice to reuse

Make the model cite, then let code check the citation. The spec's open question was how to stop a summary inventing things (devpost/spec.md → Decisions and Open Issues). The answer: every line the model writes must carry the id of the message it came from, and groundRecap / groundRerun throw away anything that doesn't match a real message. npm run reruns:sample checks it end to end (7 of 7 questions behave as expected), and test/grounding.test.js checks the code half with no API calls.

Works anywhere an AI summarises or answers from data you hold: support tickets, docs, meeting notes. Give every source an id, require ids in structured output, verify in code, show the link.

Run it again

  1. npm install, fill in .env (see .env.example and the README).
  2. npm run register, then optionally npm run seed (sample chat) or npm run seed -- 2 (a fresh episode to catch up on).
  3. npm start, then type /previously in the channel.
  4. No Discord? npm run recap:sample and npm run reruns:sample. Tests: npm test.
